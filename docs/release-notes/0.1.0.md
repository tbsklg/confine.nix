# confine 0.1.0 Release Notes

Released 2026-11-23.

## Overview

confine 0.1.0 runs on macOS on Apple Silicon and needs [Nix](https://nixos.org/download) with flakes. It is the first release named confine; earlier versions were zandy. To update an env, run this in its directory, then follow the Deprecations below:

```sh
nix flake update && nix build .#schema -o confine.schema.json && nix profile upgrade --all
```

## Broker

### New Features

- The broker runs your tools, like `glab` and `aws`, outside the sandbox with your login. The program calls them with `confine-client`; see [confine-client](../confine-client.md).
- A narrow adapter of your own can be defined in `confine.toml`; see [confine.toml](../confine.toml.md).

## confine.toml

### New Features

- An env is configured in `confine.toml`. The template's `flake.nix` isn't edited.
- `nix build .#schema -o confine.schema.json` builds a schema for completion and checks in editors that read the `#:schema` line.
- Packages outside nixpkgs come in through overlays.

### Deprecations

- Presets, gateways and adapters moved to [confine-ports](https://github.com/tbsklg/confine-ports) and are named in the TOML. An env configured in `flake.nix` needs to move to `confine.toml`.

  Before, in `flake.nix`:

  ```nix
  default = zandy.lib.mkSandboxEnv {
    inherit pkgs;
    name = "claude";
    preset = zandy.presets.claude;
    packages = [ pkgs.ripgrep ];
    gateway = zandy.gateways.bedrock { profile = "acme-bedrock"; region = "eu-west-1"; };
    adapters = [
      (zandy.adapters.gitlab { })
      (zandy.adapters.aws { profiles = [ "acme-dev" ]; })
    ];
  };
  ```

  After, in `confine.toml`:

  ```toml
  #:schema ./confine.schema.json

  name = "claude"
  preset = "claude"
  packages = ["ripgrep"]

  [gateway.bedrock]
  profile = "acme-bedrock"
  region = "eu-west-1"

  [adapters.gitlab]

  [adapters.aws]
  profiles = ["acme-dev"]
  ```

  To migrate, move the old `flake.nix` aside and run `nix flake init -t github:tbsklg/confine.nix` in the env's directory. Write your settings into `confine.toml`, as above; `filesystem` keeps its four lists, as a `[filesystem]` table. Then build the schema and run `nix profile upgrade --all`. If you need more than the TOML offers, keep using `mkSandboxEnv` in `flake.nix` with `ports.presets`, `ports.gateways` and `ports.adapters`; see [confine in Nix](../nix.md).

## Gateways

### New Features

- A gateway lets the program reach one API without seeing its key: `anthropicOauth`, `anthropic`, `bedrock` and `openai`. See [Reach an API](../README.md#reach-an-api).
- `confine-<name> --confine-secret <service>` stores a secret in confine's keychain without echo.

### Known Issues

- If a session outlives the Claude login token, requests through `anthropicOauth` might fail, because the gateway reads the token once at launch. Workaround: restart `confine-<name>`.

## Launcher

### New Features

- `confine-<name>` runs the command you name in the sandbox, or a shell without one.
- `confine-<name> --confine-config` prints the env's config, the methods the program sees and the Seatbelt profile.
- Presets get `setEnv`.

### Deprecations

- `confine-<name>` no longer starts the preset's program. Name the command:

  ```sh
  confine-claude claude              # was: zandy-claude
  confine-claude claude -p "hi"      # was: zandy-claude -p "hi"
  confine-shell npm install          # was: zandy-shell -c 'npm install'
  ```

- A preset no longer has `binary` or `args`. A preset of your own in Nix drops both; startup args go into a wrapper script in its `packages`.

## Logging

### New Features

- Sessions, broker calls, sandbox denials and proxy tunnels go to the macOS unified log, subsystem `tbsklg.confine`. See [debug log](../logging.md).

## Proxy

### New Features

- A forward proxy outside the sandbox, set in `HTTPS_PROXY`, logs each tunnel's host, port, bytes and duration under the `proxy` category. It relays `CONNECT` tunnels without decrypting them, and blocks nothing.

## Rename

### Deprecations

- zandy is renamed to confine, and zandy-ports to confine-ports: `confine-<name>`, `confine-client`, `confine.toml`, `~/.confine`, `--confine-secret` and `--confine-config`. The flakes are `github:tbsklg/confine.nix` and `github:tbsklg/confine-ports`. To move an env:

  ```sh
  mv ~/.zandy ~/.confine
  mv ~/.confine/zandy.keychain-db ~/.confine/confine.keychain-db
  cd ~/.confine/envs/<name>
  mv zandy.toml confine.toml
  sed -i "" s/zandy.schema/confine.schema/ confine.toml
  rm flake.nix flake.lock zandy.schema.json
  nix flake init -t github:tbsklg/confine.nix
  nix build .#schema -o confine.schema.json
  nix profile remove <name>                    # the old entry, as `nix profile list` names it
  nix profile add .
  ```

  Stored secrets are kept: confine finds them by service name.

## Sandbox

### New Features

- An env is a Nix derivation, read-only in the store. Only programs in its closure may be executed.
- Dot paths in the project are read-only at any depth: `.git`, `.envrc`, `.vscode` and the like. To let the program write one, add it to `[filesystem] allowWrite`.
- `flake.nix`, `flake.lock` and `confine.toml` in the project are write-protected.

### Known Issues

- If your git config is a symlink, e.g. from home-manager, git in the sandbox might not read it.
- If a script starts with `#!/usr/bin/env`, it might not run in the sandbox.
- If you run npm, it might fail to write its cache in `~`. Workaround: `npm --cache "$TMPDIR/npm"`.

### Deprecations

- An env's directory, with its `flake.nix` and `confine.toml`, belongs in `~/.confine/envs/<name>/`. The sandbox can't read or write `~/.confine`. Anywhere else, only `flake.nix`, `flake.lock` and `confine.toml` in the project are protected. To move an env, e.g. from `~/sandboxes`:

  ```sh
  mkdir -p ~/.confine/envs
  mv ~/sandboxes ~/.confine/envs/claude
  nix profile remove sandboxes                 # the old entry, as `nix profile list` names it
  nix profile add ~/.confine/envs/claude
  ```
